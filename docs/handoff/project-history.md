# 项目演化简史

## 初心与命名

项目起于把出生资料、长期记录和多体系研究放进可追溯、可撤销的私人档案，而不是让
语言模型即兴“算命”。当前产品名固定为“三际观”，确定性核心名为“三际枢”。早期工作
称谓和原型方案均已被当前命名与架构取代，不得把“三际镜”等旧称恢复为现行品牌。

## 工程阶段

- Sprint 0–1A：冻结安全边界，建立 Monorepo、时间规范化、PostgreSQL、RLS、API、
  Schema、幂等与证据表。
- Sprint 1B–3：形成三际录、规则工坊、研究推演闭环和受控 DeepSeek 成文；确定性结论
  始终不交给 LLM。
- 三际枢核心：PR #7 起把 Calendar、Signals/Inference 及后续算法收敛到独立 Python 包，
  支持无 Web、API、数据库和网络运行、Trace、Replay 与跨平台 Hash。
- 传统算法地基：PR #23 建立八字传统结构；PR #24 引入固定上游对照；PR #25 完成
  八字、受限三合紫微和京房纳甲六爻的版本化研究 Profile。PR #24 的提交由后续 PR #25
  一并进入主干。
- V1 RC：PR #26 补齐邀请制、完整出生原始记录、主体范围传统执行、部署恢复、隐私、
  开源整备和交接入口，形成 `1.0.0-rc.1` 候选。

## 当前有效方案

- PC 优先的响应式 PWA，移动端保持单列核心流程。
- PostgreSQL 是档案和执行历史唯一事实来源；私人表 FORCE RLS。
- Canonical JSON、版本 Hash、Trace、Replay、Reanalysis 和版本比较共同维护历史可复现性。
- DeepSeek 仅润色白名单字段，失败或越权时使用确定性模板回退。
- 六象、宿世、中阴、缘契和命势融合属于三际观原创研究，不伪称传统共识。

## 已取代与未来事项

已取代：浏览器会话充当历史事实源、临时算法、无版本规则、把模型输出当计算结果、
未标注混派。未来事项：许可证、公开授权、生产 KMS、数据地区、备份/删除 SLA、外部
数据再分发与生产规则审校；这些均未因 V1 RC 自动解决。
