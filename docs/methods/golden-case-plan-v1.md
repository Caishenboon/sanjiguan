# 传统方法权威金样例计划 v1

## 分层

1. `mechanical_reference`：当前自动测试，证明代码和 Hash 稳定。
2. `source_attested`：可定位到原典/正式出版方法与版本的规则样例。
3. `reviewer_signed`：合格方法审校人逐字段签署。
4. `cross_implementation`：与真正独立、明确同 Profile 的实现交叉核对。

只有 2+3 同时满足的样例才能称为权威金样例；独立实现比较是补强，不代替来源。两个产品共用同一底层库不得算两个独立证据。

## 八字计划

- 立春前/时刻/后；十二节各前/时刻/后。
- 22:59、23:00、23:59、00:00、00:59、01:00，并分别覆盖法定与视太阳时跨界。
- DST 春季缺失时间、秋季重复时间、pre-1970 历史时区与日期变更线两侧。
- 每个样例记录：原始输入、tzdb 版本、经纬度、节气算法版本、Profile、四柱、逐步 Trace、允许误差。
- 日柱至少建立跨世纪、闰年、月末、历法支持边界的独立 epoch 样例。

## 紫微计划

- 十二农历月 × 十二时支的最小覆盖；五行局和十四主星全覆盖。
- 闰月 1、15、16、月末；子时边界；阴阳年与方向组合。
- 每例由人工排盘资料或正式出版实例提供，记录流派、版本、闰月、四化、大限政策。
- 不使用来源不明的在线排盘作为唯一标准；Oracle 只能对照。

## 易经计划

- 0、1、2–5、6 动爻；八个三钱排列；64 本卦全覆盖。
- 机械 goldens 固定原始钱面、2/3 约定、爻序、本/变卦与动爻。
- 解释 goldens 将来单独按方法 Profile 建立；本轮不混入机械资产。

## 变更控制

差异必须记录工具、版本、独立性、Profile、一致项与不一致项。未确认差异进入隔离报告，禁止通过更新旧 Golden 或 Hash 消除。权威样例资产需内容 Hash、来源许可说明、审校人/日期和撤销状态。
