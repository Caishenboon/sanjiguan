# 八字多 Profile 基础四柱确定性引擎 Sprint 交付

## 交付状态

本 Sprint 完成 `sanji-engine` 内的研究型基础四柱纵向链，并接入 Owner-only API、
加密持久化、研究预览页面、RLS、Schema、Replay 和跨平台门禁。三个 Profile 均保持
`research_active + UNCONFIRMED + production_activatable=false`，没有默认主盘。

新增机械验证共 420 个参数化检查点：60 年循环、120 个月干组合、60 日日序、
120 个时干组合、36 个十二节前/等于/后位置、18 个时辰/子时边界、3 个 Profile

边界资产按其登记 Profile 执行，共 222 次结果（213 次确定性执行、9 次预期的结构化
拒绝；涉及 3 个 DST 歧义/研究窗口外案例）。

## 独立交叉验证

生产路径使用纯整数 Gregorian JDN。测试参考路径使用 Python 的 proleptic Gregorian
ordinal 对同一版本化锚点计算，且不调用生产 JDN 函数；四个日期检查点存放于
`day-epoch-1.0.0.json`。六十干支、月干起点、时干起点和十二时辰另存于只供测试的
`mechanical-reference-tables-1.0.0.json`，生产实现不读取该表。这些验证只证明工程
路径一致，不能替代传统人工审校。

## 74 例资产

原资产只有“方法政策差异”预期，不含四柱期望值。本 Sprint 不篡改它们。每个案例
对登记 Profile 进入真实 Engine：研究窗口内且时间合法的案例必须产出确定性结果；
DST gap/fold 或 1900–2099 外案例必须返回 `INPUT_INVALID`。任何
`pending_manual_review` 继续保持该分类。

## 数据库与应用

- 新表 `bazi_research_runs` 只存 Owner 研究执行；输入和完整结果加密。
- 明文只保留 Profile 版本、研究状态及内容哈希/Replay Manifest。
- 不回填旧记录，不伪造历史 Replay。
- Owner 页面显式输入出生资料和 Profile，显示修正分钟、候选四柱、边界标志和哈希。
- `/compare` 只并列 Profile，不选择“正确”主盘。
