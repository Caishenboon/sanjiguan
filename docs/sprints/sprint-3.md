# Sprint 3：核心体验与封闭研究内测

## 范围与状态

Sprint 3 建立 PC 优先的响应式 PWA 产品壳、三际录核心阅读与采集页面，以及仅限
Owner 的封闭研究试算。默认象辞来源为三际枢模板；DeepSeek 必须逐次取得外部模型调用
确认，且只接收获准的脱敏结构化摘要。

本阶段没有启用正式生产规则，没有向 member 或 viewer 开放推演，没有部署公开站点。
八字、紫微、自动宿世本卦、高修行世、大愿型、名人匹配、真实关系评分和 K 线均保持
关闭或研究占位状态。

## 产品壳与页面

核心页面包括：

- 三际录：首页元数据、六象完备度、当前断章、最近证契、待补资料与功能入口；
- 六象合参：六象资料状态和 15 个实际处理阶段；
- 三际断章：总断及 11 章长文结构，Owner 可展开技术细节；
- 宿世星图：SVG 研究图、键盘可选节点及列表替代视图；
- 中阴之门：只展示已有链路和证据不足的断点；
- 命势长图：完全虚构 fixture、置信带和表格替代；未冻结术数轨道明确禁用；
- 缘契图：真实档案只展示同意和资料网络，不展示未经批准的关系评分；
- 观照录：五类手机速记，草稿只保存在当前页面内存；
- 历次命卷：只读的版本沿革，不静默覆盖旧卷；
- 更多：手机端承接非底栏入口；
- Owner 评测入口、研究推演、知识工坊和规则工坊导航。

所有页面中的人物、命卷、证据、曲线和关系均为虚构 fixture。

## 响应式与无障碍契约

断点固定为：

| 范围 | 布局 |
| --- | --- |
| `<768px` | 手机：隐藏侧栏，显示最多五项底部导航；星图改为节点列表 |
| `768–1199px` | 平板：保留侧栏，内容卡片收为双列 |
| `1200–1599px` | PC：完整侧栏和主次多栏 |
| `≥1600px` | 宽屏：扩大内容上限与间距 |

键盘焦点采用可见金色轮廓；状态均有文字，不以颜色作为唯一信息。星图提供列表替代，
命势图提供表格替代。核心 SVG 有文字说明，长文保持可读行宽。`prefers-reduced-motion`
下禁用过渡和动画。

已在本机 Chromium 验证 390×844、768×1024、1440×900、1920×1080、
720px 宽的 200% 缩放等价视口，以及 reduced-motion；各视口均无横向溢出。

## Owner 研究试算与隐私

研究试算必须满足以下条件：

1. 服务端会话角色为 Owner；
2. 模式为 `research_preview`，档案为合成案例或明确标记的研究档案；
3. 非合成档案必须有研究模式确认；
4. 默认 `prose_provider=template`；
5. 选择 DeepSeek 时必须另行确认外部模型调用；
6. 只发送 verdict、锁定断章、获准证契摘要、获准逆证摘要和获准 Claim；
7. 不发送姓名、邮箱、精确地址、经纬度、关系身份或原始日志；
8. Provider 重试数为零；失败回退模板；
9. 保存 Token 和成本数字，不保存原始 Prompt 或模型响应到用量表；
10. 研究报告可幂等删除，生成文辞同步删除。

普通 CI 不读取或调用 `DEEPSEEK_API_KEY`。DeepSeek 继续只允许独立的手动验证流程。

## PWA 与缓存

Manifest 使用 `display=standalone`、`/profile/demo` 起始页、192 与 512 图标。页面在安全
上下文注册 Service Worker。缓存白名单仅含图标和 manifest；`/api/`、`/profile/` 和
Prompt 路径明确旁路，不建立离线敏感数据库。详细策略见
[PWA 安装与缓存策略](../pwa/install-and-cache-policy.md)。

## 数据库与 API

迁移 `0010_sprint3_private_research_experience.sql` 为分析运行增加象辞来源与两类确认时间，
并建立仅 Owner 可访问的 `model_usage_records`。表启用并强制 RLS，只保存 Provider、
模型名、Token、估算成本和时间。

API 增加 Owner 研究分析创建/运行、信号、候选、检索、报告和报告删除契约。OpenAPI 快照
已同步。UUID 继续由应用层生成，所有变更路由继续使用 24 小时幂等键契约。

## 验收门禁

- Python 普通测试和内存 API；
- PostgreSQL 16 空库迁移、重复迁移、漂移、RLS/并发和 HTTP→PostgreSQL E2E；
- Sprint 0 至 Sprint 3 静态门禁；
- Schema、OpenAPI、文档链接、品牌语言和受阻术数门禁；
- Web production build；
- Sprint 3 响应式、PWA、隐私和无障碍契约；
- 全历史 Gitleaks 与工作树 Secret Scan。

本地未提供 Docker/PostgreSQL，因此 PostgreSQL 16 的最终运行证据以 GitHub Actions 为准。

## 已知限制与下一阶段建议

象辞文学质量按已批准原则记录为技术债，详见
[象辞文学质量技术债](../technical-debt/prose-quality.md)。下一阶段建议先由产品负责人
审核本 PR 的完整界面、封闭研究试算和删除流程；在独立批准前，不扩大角色、规则、数据
来源或外部模型权限。
