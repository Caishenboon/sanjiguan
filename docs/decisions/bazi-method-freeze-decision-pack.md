# 八字基础排盘方法冻结决策包

状态：等待项目所有者逐项决定。Codex 建议不是最终决定。

## BZ-001：时间输入与 Calendar 复用

- **问题**：哪些出生时间资料是确定性输入，Calendar 与八字的边界在哪里。
- **选项**：A 仅民用时间；B 民用＋平太阳；C 民用＋视太阳；D 民用记录＋平/视太阳候选＋换界敏感性。
- **依据**：Owner D-001；IANA named-zone 历史；USNO 对平/视太阳时及经度差的定义。
- **反证/限制**：IANA 早期历史可能修订；天文定义不裁定命理正统。
- **输出影响**：可能改变后续日界、时界与节气边界候选。
- **典型案例**：`TIME-LONGITUDE`、`TIME-APPARENT-CROSS-DAY`。
- **复杂度**：D 高，需要保存校正链和多候选。
- **回放影响**：必须锁定 tzdb、Calendar、经纬度精度与校正版本。
- **Codex 建议**：遵守已冻结 D-001，采用 D 作为产品数据流，不将任何候选称为主盘。
- **是否足以冻结**：工程数据流已冻结；命理主盘未冻结。

## BZ-002：年柱边界

- **问题**：立春天文瞬时、含立春民用日或其他历法点何时切换年柱。
- **选项**：`LICHUN_ASTRONOMICAL_INSTANT`；`CIVIL_DAY_CONTAINING_LICHUN`；其他经来源审校的方法。
- **依据**：HKO 证明节气是太阳到达预定黄经的瞬时；仓库可计算该瞬时。
- **反证/限制**：天文瞬时不自动证明八字年柱取法；当前没有签字命理边界样例。
- **输出影响**：边界附近年柱及依赖项不同。
- **典型案例**：`YEAR-LICHUN-BEFORE/AT/AFTER`。
- **复杂度**：机械实现低，来源与回放治理中。
- **回放影响**：需锁定节气实现、包含侧和时区换算次序。
- **Codex 建议**：把天文瞬时保留为候选，等待审校，不冻结。
- **是否足以冻结**：否。

## BZ-003：月柱边界

- **问题**：十二“节”、全部二十四节气或含节气民用日如何切月。
- **选项**：`TWELVE_JIE_ASTRONOMICAL_INSTANT`；`TWENTY_FOUR_TERMS`；`CIVIL_DAY_CONTAINING_JIE`。
- **依据**：HKO 明确二十四节气含十二中气与十二节气、相间排列。
- **反证/限制**：工程来源不裁定八字只用哪些节点；传统来源与流派审校尚缺。
- **输出影响**：月界附近月柱与后续所有月令解释不同。
- **典型案例**：十二“节”各自 `BEFORE/AT/AFTER`，另有中气对照。
- **复杂度**：机械中，案例与审校高。
- **回放影响**：锁定目标黄经、瞬时、时区和包含侧。
- **Codex 建议**：保留十二节瞬时候选，但不冻结。
- **是否足以冻结**：否。
- **项目所有者最终决定**：

## BZ-004：日柱换日

- **问题**：民用午夜、子初或早晚子时拆分。
- **选项**：`DAY_BOUNDARY_00_CIVIL`；`DAY_BOUNDARY_23_ZICHU`；`LATE_EARLY_ZI_SPLIT`。
- **依据**：D-002 已登记三类争议；当前证据包将“缺少合格来源”本身记录为 Claim。
- **反证/限制**：没有足够的定位来源、同流派判例和审校人，不能宣称某一项是唯一古法。
- **输出影响**：23:00–00:59 可能改变日柱与时干。
- **典型案例**：22:59、23:00、23:59、00:00、00:59、01:00 和太阳时跨界。
- **复杂度**：单规则低，双轨传播与回放中高。
- **回放影响**：必须持久化 day-rollover method ID 与校正次序。
- **Codex 建议**：保持三候选，D-002 未冻结前不得实现柱值。
- **是否足以冻结**：否。
- **项目所有者最终决定**：

## BZ-005：时柱边界与时间基准

- **问题**：十二双时辰使用校正前或校正后时间，边界包含哪一侧。
- **选项**：民用时间；地方视太阳时；双时间候选。
- **依据**：Calendar 已能生成候选和跨双时辰敏感标志。
- **反证/限制**：Calendar 的双时辰桶只是边界检测，不是命理时柱算法。
- **输出影响**：每个奇数小时边界、子时与太阳校正跨界处不同。
- **典型案例**：12 个双时辰边界、未知/低精度/多候选时间。
- **复杂度**：中。
- **回放影响**：需锁定基准时间、包含侧、地点精度和未知时间策略。
- **Codex 建议**：采用双候选敏感性作为研究数据流，等待流派决定主规则。
- **是否足以冻结**：否。

## BZ-006：历法与历史范围

- **问题**：公历改革前日期使用外推格里历还是地点历史历法，支持何种范围。
- **选项**：1900–2099 研究窗口；全量外推格里历；地点历史改革表。
- **依据**：当前 ISO 日期解析采用格里历结构；IANA 主要保证 1970 后一致性并提示早期资料限制。
- **反证/限制**：没有地点历法改革数据和生产 SLA。
- **输出影响**：历史日序及全部柱值会受影响。
- **典型案例**：当前案例库暂不把改革前日期设为正式门禁。
- **复杂度**：地点历史历法最高。
- **回放影响**：必须锁定 calendar basis 和支持窗口。
- **Codex 建议**：先冻结窄研究窗口；改革前输入结构化拒绝，不静默外推。
- **是否足以冻结**：需 Owner 决定范围。
