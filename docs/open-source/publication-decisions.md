## 工程推荐的最短公开路径

以下是工程建议，不是已经生效的法律或产品决定：

| ID | 推荐选择 | 原因 |
|---|---|---|
| O-001 | 项目原创软件采用 `AGPL-3.0-or-later` | 允许公开协作，同时要求经网络提供修改版服务的一方提供相应源代码；最终适用性仍应由权利人确认 |
| O-002 | 仅对项目原创规则数据、方法文档和非软件知识结构采用 `CC-BY-SA-4.0` | 与代码分开治理；第三方、受限、隐私和授权不清资产明确排除 |
| O-003 | 由产品负责人填写希望公开展示的版权/署名名称和起始年份 | 工程不能推定自然人姓名、法人或笔名 |
| O-004 | 采用“代码与内容开放，名称和 Logo 不随许可证授权”的保守品牌政策 | 避免衍生项目冒充官方版本；候选文本见 `TRADEMARKS.md` |
| O-005 | 若负责人知情接受邮箱公开，则保留当前历史 | 不改变 Commit SHA、Replay 引用和审计链；若不能接受，应改走经单独授权的干净公开快照，不能静默重写历史 |
| O-006 | 由具备相应传统/传承资格的审校人签署知识边界复核 | Codex、LLM 或普通工程审核者不能代签 |
| O-007 | 当前公开范围继续排除外部原始数据、真实人物 Fixture 和敏感人物推断；由法律/隐私审核者确认这一范围 | 不以平台元数据标签替代再分发权利判断 |
| O-008 | 产品负责人按 Manifest 人工核对 26 张合成截图及 Demo/Fixture | 机器只能确认 Hash 和标记，不能确认是否影射真实身份 |
| O-009 | 前八项落地并通过 `--require-public-ready` 后，再授权切换 Public | GitHub 会公开 Git 历史、Actions 历史和日志，必须作为最后一步 |

正式签署格式与审校记录见[公开发布授权与复核包](public-release-authorization-packet.md)。
